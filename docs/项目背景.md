## 二、行业背景：2025 年白酒行业进入深度调整期（真实数据）

2025 年，白酒行业从"总量增长"转入"存量竞争"，**20 家样本公司出现剧烈分化**。根据本项目已入库的 60 份年报与财务数据统计：

- **20 家公司中 19 家营业收入同比下滑，仅山西汾酒逆势增长 +7.52%**（金徽酒 +7.03%、皇台 +4.95%、今世缘 +0.40% 为小幅正增长）；
- **五粮液营业收入同比 -54.55%、归母净利润 -71.89%**，为样本中降幅最大；
- **贵州茅台毛利率 91.18% 仍居第一**，但营收同比 -1.20%、净利润 -4.53%，为多年来首次小幅下滑；
- **ROE 连续三年下降的公司有 13 家**（五粮液、今世缘、伊力特、口子窖、天佑德酒、山西汾酒、岩石股份、水井坊、泸州老窖、洋河股份、舍得酒业、迎驾贡酒、酒鬼酒）；
- 2023→2025 营收 CAGR：山西汾酒 +10.12%、金徽酒 +7.03%、贵州茅台 +6.90%、皇台酒业 +4.95%；降幅最大为岩石股份 -84.46%、酒鬼酒 -37.43%、五粮液 -30.24%。

**行业分化意味着"研究工作量"和"判断难度"同时上升**：同样是"营收下滑"，有的公司是主动去库存、有的是渠道崩坏、有的是产品结构问题；研究员必须逐份读年报的"管理层讨论与分析"、逐项对财务指标、逐个查机构持仓，才能给出有依据的判断。

**结论：这个场景不缺数据，缺的是"把分散信息变成可回答问题"的能力。**

## 三、业务痛点（可量化）

| # | 痛点 | 现状（示例测算，可替换） |
|---|---|---|
| 1 | **年报阅读量巨大** | 单份年报 141–243 页、平均约 187 页；20 家公司 60 份共 **11,210 页、1,072.65 万字**；研究员精读一遍需数十小时 |
| 2 | **跨公司对比靠手工** | 20 家公司 × 3 年 × 13 项指标 = **780 个数据点**，手工从年报/终端拉表 2–3 天；换一次对比维度就要重做 |
| 3 | **信息分散在多种载体** | "为什么下滑"在 PDF 原文里、"指标是多少"在 Excel/终端里、"谁在买"在股东名册里、"今天什么价"在行情软件里，多个工具来回切 |
| 4 | **口径与时效风险** | 单位（元/万元/亿元）、母公司/合并口径、报告期（年报/快报）不一致容易取错数；2025 调整期信息更新快，旧结论容易过期 |
| 5 | **新人培养成本高** | 行业研究方法、公司基本面、数据口径要 3–6 个月带教，知识沉淀在个人脑子里 |
| 6 | **通用大模型不能直接用** | 会编数字、无法给出处、答不了指标计算（"CAGR 排名"）和股东关系（"共同持仓"）类问题 |

**一句话总结痛点**：研究员真正需要的是"**能查原文、能算指标、能看关系、还能给出处**"的助手，而不是一个只会聊天的机器人。

## 六、业务流程

### 离线（知识库构建）

```
巨潮年报 PDF（60 份） ──PyMuPDF解析──► 页眉页脚清理 / 目录页识别 / 章节切分
        │                                        │
        │                                 父子块切分（父块=章节级，子块=300字）
        │                                        │
        │                              BGE-M3 稀疏+稠密编码
        │                                        ▼
        │                                    Milvus（metadata：公司/年份/章节/页码）
        │
        ├── 东财财务指标（13 项，60 条）──► 清洗入库 MySQL ──► NL2SQL
        └── 东财十大股东（186 条）──► 清洗 ──► Neo4j（规划）/ MySQL 股东表
```

### 在线（问答）

```
用户提问
  └─► 意图识别/路由（规则 + 自训练 BERT 兜底）
        ├─ 文档题 → Milvus 混合检索（BGE-M3 + BM25 RRF）→ 取 Top-K 原文 → 页码引用
        ├─ 指标题 → DeepSeek 生成 SQL → sqlglot 安全校验 → MySQL 执行 → 结论
        ├─ 行情题 → 腾讯实时行情 + 年报基本面（带延时/免责声明）
        ├─ 关系题 → 股东表 SQL（Neo4j 规划）
        └─ 兜底 → RAG 明确"未找到"时转 LLM 通用回答（标注非年报原文）
              ▼
        LLM 生成答案（流式 SSE/WebSocket）+ 引用（公司/年份/页码）
              ▼
        会话历史 + 报告导出（Word/Markdown）
```

## 七、为什么是"现在"（项目时机）

1. **行业处于分化期**：2025 年白酒行业深度调整，单靠"看总量"的判断方式失效，分化的定量+定性研究需求集中在头部机构；
2. **技术条件成熟**：DeepSeek 等国产大模型 API 成本低、BGE-M3 中文检索效果好、Milvus 开源生态完善，一个人可做完整闭环；
3. **数据可得**：年报法定披露（巨潮）、财务/股东数据公开（东财），不依赖内部数据；
4. **合规边界清晰**：只做"信息检索 + 数据计算 + 关系查询"，不做投资建议/预测，风险可控（UI 与文档均声明）。

## 九、项目价值

**业务价值**
- 研究员单问题查证时间从 10–30 分钟缩短到秒级，跨公司对比从天级降到分钟级；
- 答案带出处，降低"AI 编数字"带来的合规与信任风险；
- 沉淀行业知识库，新人上手周期缩短（示例：3–6 个月 → 1–2 个月）；
- 自动识别"ROE 连续下降、营收利润背离"等风险信号，辅助风控。

**技术价值**
- 多源异构融合（非结构化文档 + 结构化表 + 股东数据 + 实时行情），覆盖 RAG、NL2SQL、意图识别、Agent 路由等方向；
- 章节感知切块 + 页码引用，解决长文档"可检索但不可溯源"的行业痛点；
- 自训练金融意图 BERT + OOD 评估；自建 32 题检索/答案评测集（hit@5 95%、SQL 12/12、引用率 85%），并用 RAGAS 评测（Faithfulness 0.878、Answer Relevancy 0.928、Context Precision 0.755、Context Recall 0.636），效果可量化。

**组织价值**
- 知识不随人员流动丢失；研究口径统一（同一问题同一答案同一出处）。
