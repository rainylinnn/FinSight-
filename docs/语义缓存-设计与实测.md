# 语义缓存设计与实测报告（BGE-M3 向量缓存）

> 结论先行：语义缓存已实现并用**真实 BGE-M3** 校准过阈值，12 组判定全部正确（12/12）。
> 缓存命中可省掉「向量检索 + LLM 生成」整条链路，RAG 类问题从 10–15 秒降到秒回。

---

## 1. 为什么做

RAG 类问题（问年报原文）一次要 10–15 秒：BM25 召回 + 向量召回 + RRF 融合 + LLM 生成。
答辩/演示时同一个问题往往要问两遍（先问再追），每次都走完整链路很浪费。
语义缓存把「问过的问题 → 答案」按向量相似度存起来，命中直接复用。

## 2. 架构

```
new_main.IntegratedQASystem.query()
   │
   ├─ _cache_lookup()   ← 查缓存
   │     ├─ 归一化：全角→半角、去标点、压空白
   │     ├─ BGE-M3 编码（复用 VectorStore.embedding_function，不额外加载模型）
   │     ├─ 与历史向量做余弦比对
   │     └─ 六道判定全过才命中 → 直接返回答案 + 抛 cache 事件给前端
   │
   └─ 正常链路 → 产出答案 → _cache_store() 写回缓存
```

代码位置：

| 文件 | 职责 |
|---|---|
| `services/semantic_cache.py` | 缓存本体：后端、检索、六道判定、统计 |
| `new_main.py` | 接入问答主链路（`_cache_lookup` / `_cache_store`） |
| `app.py` | 透传 `cache` 事件（SSE/WS）、`/api/cache/stats`、`DELETE /api/cache` |
| `static/index.html` | 侧栏「语义缓存」状态行 + 回答下方命中徽标 |
| `scripts/calibrate_cache_threshold.py` | 阈值校准（真实 BGE-M3） |
| `scripts/warm_cache.py` | 预热答辩高频问题 |
| `tests/test_semantic_cache.py` | 单元测试（28 项，不需要任何服务） |

## 3. 存储设计

### Redis 后端（默认，跨进程共享）

| Key | 类型 | 内容 |
|---|---|---|
| `finsight:sem:v:<hash>` | STRING | float32 向量原始字节（4 KB） |
| `finsight:sem:e:<hash>` | STRING | 条目 JSON（query / answer / mode / route / 时间戳） |
| `finsight:sem:index` | ZSET | 索引，score = 创建时间（用于取最近 N 条 + 清理） |
| `finsight:sem:stats` | HASH | hits / misses / writes |
| `finsight:sem:hits` | HASH | 每条目的命中次数 |

TTL 默认 2 小时，最多 500 条，超出按 ZSET 分数从旧到新淘汰。

### 内存后端（Redis 连不上时自动降级）

进程内 dict + OrderedDict 做 LRU，检索用 numpy 暴力比对。
本机默认没装 Redis，演示时走的就是这条路径（启动日志会写明「降级为进程内内存模式」）。

> 为什么必须能降级：缓存是加速器，不是正确性的前提。Redis 挂了不应该让整个问答系统起不来。

## 4. 六道判定门槛（核心）

| # | 门槛 | 挡住什么 | 阈值 |
|---|---|---|---|
| ① | 向量余弦 | 完全无关的问题（0.44–0.47） | ≥ 0.85 |
| ② | 实词 Jaccard | 极端词面无关 | ≥ 0.2（弱门槛） |
| ③ | 指标类别 | 营收 vs 净利 vs 毛利率… | 不相交即拒 |
| ④ | 年份 | 2025 年营收 vs 2023 年营收 | 不相交即拒 |
| ⑤ | 方向 | 营收最高 vs 营收最低 | high/low 相反即拒 |
| ⑥ | 序数口径 | ROE 前三 vs ROE 前十 | 不相交即拒 |

## 5. 阈值是怎么定出来的（实测数据）

`uv run python scripts/calibrate_cache_threshold.py`（真实 BGE-M3，12 组问题，约 2 分钟）

### 5.1 纯向量相似度

| 分组 | 期望 | 相似度 |
|---|---|---|
| 「2025年营业收入最高的公司」/「哪家公司2025年营收最高」 | hit | 0.9068 |
| 「贵州茅台2025年营业收入是多少」/「贵州茅台2025年营收多少」 | hit | 0.9767 |
| 「茅台2025年毛利率」/「贵州茅台2025年的毛利率是多少」 | hit | 0.9218 |
| 「2025年ROE最高的前三家公司」/「哪些公司2025年ROE排名前三」 | hit | 0.9491 |
| 「五粮液2025年归母净利润」/「五粮液2025年净利润是多少」 | hit | 0.9341 |
| 「2025年营业收入最高的公司」/「2025年归母净利润最高的公司」 | miss | 0.8949 |
| 「茅台2025年毛利率」/「茅台2025年资产负债率」 | miss | 0.8703 |
| 「2025年营收TOP3」/「2025年ROE TOP3」 | miss | 0.7731 |
| 「2025年营业收入最高的3家公司」/「2025年净利润最高的3家公司」 | miss | **0.9302** |
| 「2025年营业收入最高的公司」/「茅台年报里的经营风险有哪些」 | miss | 0.4452 |
| 「贵州茅台2025年营业收入」/「贵州茅台2023年营业收入」 | miss | 0.8605 |
| 「2025年营收排名」/「白酒行业的竞争格局如何」 | miss | 0.4745 |

**同义组最低 0.9068 < 异指标组最高 0.9302 —— 分布交叉，纯向量阈值无解。**
调高会漏掉同义改写（「营收」vs「营业收入」），调低会把「营收TOP3」答成「净利TOP3」。

### 5.2 踩过的坑：Jaccard 不能当硬门槛

第一版把「实词 Jaccard ≥ 0.45」当第二道硬门槛，结果同义改写反而被挡：

| 问题对 | Jaccard | 结果 |
|---|---|---|
| 营业收入最高的公司 / 哪家公司2025年营收最高 | 0.333 | 被挡（漏命中） |
| ROE最高的前三家公司 / 哪些公司2025年ROE排名前三 | 0.400 | 被挡（漏命中） |

原因：`jieba.cut_for_search` 把「营业收入」切成 `营业 + 收入`，而「营收」是整词，
近义词在词面上反而没有交集。**词面重合度和语义相似度是两回事。**

改法：Jaccard 降级为弱门槛（0.2），正确性交给 ③④⑤⑥ 四道精确判定。

### 5.3 最终判定结果（真实模型跑完整逻辑）

**12 / 12 全部正确**（5 组同义改写命中，7 组该拒的拒绝）。

## 6. 缓存范围

| 链路 | 缓存 | 原因 |
|---|---|---|
| 财务指标（SQL） | ✅ | 数据来自年报，答案确定 |
| 年报原文（RAG） | ✅ | 知识库内容固定 |
| 行情（market） | ❌ | 实时数据，缓存就是错的 |
| LLM 通用回答 | ❌ | 含时效性说明与风险提示 |
| 追问（「利润呢」） | ❌ | 答案依赖上下文，短问题易误命中 |
| 「未找到」类回答 | ❌ | 没信息，缓存无意义 |

## 7. 效果

- 单次 RAG 问答：10–15 秒 → 命中缓存后 **< 1 秒**（省掉检索 + 两次 LLM 调用）
- 命中时前端会挂一个 `⚡ 语义缓存命中 · 相似度 xx%` 徽标
- 侧栏「语义缓存」实时显示：后端 / 条目数 / 命中数 / 命中率
- `GET /api/cache/stats` 取统计，`DELETE /api/cache` 清空

## 8. 用法

```bash
# 单元测试（不需要 MySQL / Milvus / Redis / 模型）
uv run python tests/test_semantic_cache.py

# 阈值校准（真实 BGE-M3，约 2 分钟）
uv run python scripts/calibrate_cache_threshold.py

# 预热答辩高频问题（需要 MySQL / Milvus / LLM 在线）
uv run python scripts/warm_cache.py
uv run python scripts/warm_cache.py --repeat    # 再问一遍对比命中耗时
```

配置（`config.ini`）：

```ini
[cache]
semantic_enabled = true
semantic_threshold = 0.85
semantic_min_jaccard = 0.2
semantic_ttl = 7200
semantic_max_entries = 500
semantic_candidate_limit = 200
```
