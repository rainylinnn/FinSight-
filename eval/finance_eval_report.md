## 二、检索评测（BM25 关键词融合 A/B）

| 配置 | hit@5 | MRR | 平均检索延迟 |
|---|---|---|---|
| BGE-M3 混合检索 + **BM25 RRF 融合（当前默认）** | **95.0%** | **0.885** | 1.44 s |
| 仅 BGE-M3 混合检索（关闭 BM25） | 90.0% | 0.767 | 0.53 s |

**结论**：BM25 + RRF 融合把 hit@5 从 90% 提到 **95%**、MRR 从 0.767 提到 **0.885**，代价是单次检索多约 0.9 秒（CPU 上可接受）。

## 五、结论与局限

**结论**：
1. 检索层：BM25+RRF 融合有效，hit@5 95%、MRR 0.885，达到可用水平；
2. 数据层：SQL 数值回答 12/12 命中，适合"指标类问题走数据库"的设计；
3. 生成层：RAG 答案关键词命中 95%，引用率 85%，仍有 1 类"章节选错"问题需优化。

**局限**：
- 评测集为自建小样本（32 题），需扩充到 100+ 题并交叉人工标注；
- 未开 reranker（CPU 单次 30–60s 不可用），有 GPU 时可对比开启后的 hit@5/MRR；
- 未做并发压测（当前为串行单用户测量），P95 反映的是 CPU 单请求延迟；
- 文档题关键词判定较粗，后续可改为"引用页码是否落在标准答案页"的严格判定。

## 六、后续优化清单

1. 扩充评测集到 100+ 题（覆盖 20 家公司 × 多类问题）；
2. 章节感知检索：问题含"风险/战略/渠道"时优先检索"第三节 管理层讨论与分析"；
3. GPU 下开启 bge-reranker 做 A/B，补 hit@5/MRR 与延迟对比；
4. 并发压测（10/50 并发）+ token 成本统计；
5. 失败样本回归：把本次 1 条未命中 + 3 条无引用纳入回归集。

## 七、RAGAS 评测（2026-10-20）

- 脚本：`scripts/run_ragas_eval.py`；结果：`eval/ragas_results.json`
- 样本：11 道文档题（覆盖 10 家公司），每题为「问题 + 参考答案 + 检索上下文 + 生成答案」
- 裁判：LLM = DeepSeek `deepseek-flash`（OpenAI 兼容），Embedding = 本地 BGE-M3

| RAGAS 指标 | 分数 | 含义 |
|---|---|---|
| Faithfulness（忠实度） | **0.878** | 回答内容有多少能被检索上下文支持，越高越不易幻觉 |
| Answer Relevancy（答案相关性） | **0.928** | 回答与问题的相关程度 |
| Context Precision w/ Ref（上下文精度） | **0.755** | 检索到的上下文里相关内容占比/排序 |
| Context Recall（上下文召回） | **0.636** | 参考答案的要点被上下文覆盖的比例 |

**解读**：
1. 忠实度 0.878、相关性 0.928 → 生成层质量可用，答案基本不脱离上下文；
2. 精度 0.755、召回 0.636 → **瓶颈在检索层**：命中了问题关键词，但参考答案的细节点没被完整覆盖（例如"茅台分红"细节、"洋河渠道策略"具体措施）；
3. 与前面"关键词 hit@5 95%"的差异说明：命中相关 chunk ≠ 覆盖标准答案全部要点，RAGAS 口径更严格。

**改进方向**：
- 章节感知检索（风险/战略类问题优先检索第三节）；
- 提高 candidate_m 或对 top-k 做 rerank（需 GPU）；
- 父子块策略调参（父块 1200 → 800/1600 对比）；
- 把 RAGAS 纳入回归：每次调参后重跑 11 题，看四项指标变化。
