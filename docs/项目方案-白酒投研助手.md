## 2. 项目定位与业务故事

**项目名参考**：FinSight 酒研助手 / 酒研纵横 / 财报通·白酒行业版

**一句话定位**：
> 面向券商/基金行业研究员和投资者关系的**白酒行业智能投研工作台**——把"读年报（文档）、查指标（SQL）、看股东（图谱）、看行情（实时数据）"几条链路合成一个对话式助手。

**业务故事（答辩 PPT 用）**：
> 2025 年白酒行业进入深度调整期，20 家样本公司中 19 家营收下滑、五粮液营收同比 -54.55%，但山西汾酒逆势增长 7.52%、茅台毛利率 91.18% 仍居第一。行业分化加剧时，研究员每天要翻几十份、每份上百页的年报：既要找"下滑原因/战略调整/渠道变化"的原文，又要横向对比财务指标，还要看机构持仓和实时行情。传统方式 1 份年报读 30 分钟，20 家公司对比要 2–3 天。本系统用 RAG + NL2SQL + 行情服务，让研究员用自然语言完成"找原因、比指标、看股东、看行情、出报告"。

## 3. 产品形态：三类问答 + 一个工作台（当前已实现）

| 问题类型 | 例子 | 走哪条链路 |
|---|---|---|
| **文档事实题** | "五粮液 2025 年报怎么解释营收下滑？" | PDF RAG（返回原文 + 公司/年份/页码/章节引用） |
| **指标计算题** | "2025 年营收 TOP3？哪家逆势增长？" | MySQL + NL2SQL（返回结论/表格，SQL 只写日志） |
| **行情题** | "茅台今天股价多少？" | 行情服务（腾讯实时行情 + 年报基本面 + 风险提示） |
| **关系题** | "哪些机构同时重仓 10 家以上白酒公司？" | 股东表 SQL 兜底（Neo4j 图查询为规划项） |
| **复合题** | "对比茅台/汾酒/老窖 2025 盈利质量并给结论" | 意图路由：SQL 取数 + RAG 找解释 + 生成对比 |

**产品页面（当前静态单页，Vue 版规划中）**：
1. 对话页：多公司/知识库选择、功能模式（智能问答/财务指标/年报原文/行情数据/多公司对比/股东图谱）、流式输出、Markdown 表格渲染
2. 侧边栏：白酒板块指数、自选公司实时行情、历史会话、研究工具（导出报告/公司对比/公司速览/问题模板）
3. 引用溯源：答案内【公司 年份 第X页】；引用卡片/原文高亮为规划项
4. **对比图表**（规划）：ECharts 营收增速/毛利率/ROE 对比
5. **股东关系图**（规划）：ECharts graph 展示"公司-股东"二部图
6. **评测报告页**（规划）：检索命中率、SQL 准确率、引用准确率、RAGAS 指标

## 4. 功能模块 × 数据映射

| 模块 | 用的数据 | 关键技术 |
|---|---|---|
| 财报知识库构建 | 60 份 PDF（按公司/年份 metadata） | PDF 解析、章节识别、父子块、页码映射 |
| 财报问答 | PDF chunk + metadata | BGE-M3 稀疏+稠密混合检索 + BM25 RRF + 引用溯源（reranker 可选） |
| 指标问答（NL2SQL） | `financial_indicators` → MySQL | Schema 设计、Text-to-SQL、sqlglot 安全校验、结果解释 |
| 行情问答 | 腾讯行情 + MySQL 基本面 | 实时报价、PE/PB、市值、风险提示 |
| 行业对比看板 | MySQL + 前端图表 | 静态页面 + ECharts（规划） |
| 股东关系图谱 | `holders` → Neo4j | 图建模、Cypher、多跳查询、图可视化（规划） |
| 复合问答复核 | 多路结果融合 | 意图路由 + 结果融合 + 兜底策略 |
| 评测 | 自建业务题 + 意图模型评估 | 检索命中率、SQL 执行准确率、引用准确率、RAGAS（规划） |
| 报告导出 | 会话历史 | python-docx 导出 Word/Markdown |

**MySQL 当前表**（实际 5 张）：
```
companies(code, name, industry, first_holder, ...)
financial_indicators(code, report_year, total_operate_income, parent_netprofit, ...13 指标)
holders(code, end_date, holder_rank, holder_name, hold_num, hold_ratio, hold_change)
documents(code, report_year, title, file_path, pages)
conversations(session_id, question, answer, timestamp)
```

**Neo4j 建议模型**（规划）：
```
(:Company {code,name})-[:HAS_HOLDER {ratio,rank,end_date}]->(:Holder {name,type})
(:Company)-[:BELONGS_TO]->(:Industry {name:"白酒"})
```
可支持的多跳：`(Holder)<-[:HAS_HOLDER]-(Company)` → 共同股东；"某基金重仓的 20 家公司"。

## 6. 技术架构

```
静态单页（HTML + marked.js，Vue 版规划）
        │ HTTP / SSE / WebSocket
FastAPI（app.py）
  ├── 意图识别：规则优先（公司/年份/指标/文档/行情信号）+ 自训练 BERT 兜底
  ├── 工具1：Milvus 检索（BGE-M3 稀疏+稠密 + BM25 RRF，reranker 可选）
  ├── 工具2：MySQL NL2SQL（DeepSeek 生成 SQL → sqlglot 校验 → 执行 → 解释）
  ├── 工具3：行情服务（腾讯实时行情 + 东财 K 线，缓存 30s/1h）
  ├── 工具4：报告导出（python-docx / Markdown）
  └── 工具5：图表数据接口（ECharts option，规划接入前端）
  ├── 文档管道：PyMuPDF 解析 → 章节识别 → 父子块 → 元数据 → Milvus
  └── 用户/会话：MySQL + Redis（可选）
数据层：MySQL 8 / Milvus / Redis / 本地 BGE-M3 / DeepSeek API（无 Docker 依赖）
```

**为什么多源**：金融问题天然分几类（文档解释、指标计算、关系查询、实时行情），硬用纯 RAG 回答指标题容易错、用 SQL 回答"为什么"也不行——多源分工是业务要求，不是过度设计。

> "这是一个白酒行业智能投研助手。2025 年行业深度调整，20 家公司 19 家营收下滑、分化剧烈，研究员读年报、比指标、查股东非常耗时。我把 60 份年报做成向量知识库做原文问答和引用溯源，把财务指标做成 MySQL 支持自然语言查数，把股东和行情做成扩展服务，再用意图识别把几类能力路由起来。评测上，我训练了金融意图 BERT（1200 条数据、9:1 划分），并对知识库外问题做了统一兜底。"

**和 EduRAG 的差异（一句话）**：
> "EduRAG 是单源纯文本知识库；这个项目是多源异构（PDF 长文档 + 结构化指标 + 股东关系 + 实时行情），覆盖 NL2SQL、意图识别、行情扩展等 EduRAG 没做的技术点。"

## 12. 风险与合规

1. **不是投资建议**：UI/README 写明"仅供信息检索与研究，不构成投资建议"；
2. **数据来源合规**：年报为法定公开披露信息、东财为公开数据，仅学习/演示、不再分发；
3. **口径一致**：所有指标注明"数据来源：东方财富/年报，单位：元，报告期：YYYY"；
4. **边界控制**：知识库没有的内容（行情走行情服务并声明延时/免责；预测/荐股仍由 LLM 通用回答并风险提示），不编造数据；
5. **不要过度承诺**：不承诺"预测涨跌/选股"，只做"信息检索 + 数据计算 + 关系查询"。
